[Context]

This file is a specification of this format, and also a valid example of this format.

`.song.txt` files contain different types of content.


[Sections]

Sections are marked by square brackets (eg `[Intro]`). We can assume that they are standalone on a line. They should be rendered in bold and highlighted in yellow. ✓
We can have subsections by adding more brackets, eg `[[Chorus]]`): these should also be bold yellow. ✓


[Prose]

We can have prose anywhere in a `.song.txt`. This should just be rendered with default colours. ✓


[Tablature]

Guitar tablature is a format to represent sequence of notes as played on a guitar. It looks like this:

e|-----------4--|--1-----------|--3-----------|--3------------|
B|--------1-----|-----2-----2--|--------------|---------4--1--|
G|--3-----0--0--|-----1--0--0--|--1-----------|---------------|
D|--------1-----|-----1--------|--5--1--------|------1--1-----|
A|--4--3--------|--1-----1-----|--5--3--3--3--|---------3--1--|
E|--3-----------|--1-----------|-----1--------|------3--4--4--|

Each line is a guitar string, the numbers are the fretted notes, played sequentially from left to right.

[[Rendering]]
1. String names (EADGBe at the start of the line) MUST be in blue ✓
2. Dashes MUST be in blue ✓
3. everything else in white ✓

[[Motions]]
1. Motions like `w` MUST stop on `|` (as well as `dw`, `cw`...) ✓
2. Motions like `w` MUST NOT stop on `-` ✓
3. `L` (uppercase) MUST jump to the next `|` ✓
4. `H` (uppercase) MUST jump to the previous `|` ✓

[[Editing]]
1. `||` should lint the current tablature. ✓
    1.1 If some pipes bounding a bar are not vertically aligned across all strings, add dashes as necessary to align them. ✓
    1.2 Trim start and end dashes so that there is exactly 2 dashes after/before the pipes bounding the bar. ✓
    1.3 Split up numbers that are overlapping but not aligned (when a number is 2-digits, the second digit might overlap with another number on a different line), by pushing the second number to the right with dashes. There needs to be 1 dash between the numbers. ✓
2. In normal mode, `_` should insert a dash (`-`) at the cursor's column position on every line of the tab. ✓
3. `<leader>t` should enter a special "tablature" mode. ✓
    3.1 `a` should create space for a new note to be entered. ✓
        3.1.1 it should add dashes to the right (across all lines) to create space for a new note: at least one dash separation with the previous note and the next note (or the pipe). ✓
        3.1.2 it should move the cursor to where the new note would be: one dash apart from the current note ✓
    3.2 `w` should move to the next note on the line, not stopping at dashes or pipes. `b` does the opposite (move to previous note). ✓
    3.3 `l` and `h` move across notes. ✓
        3.3.1 `l` should move to the column where _any_ line has a note. ✓
        3.3.2 If the cursor is at the last note of the tablature, `l` should behave as `a` so that new notes can easily be appended to the tablature. ✓
        3.3.3 `h` does the opposite (moving left), except it does not behave as `i` (no mirroring requirement 3.3.2). ✓
    3.4 numbers should enter the note: replace the character under cursor with the number.
4. An edit should trigger linting
    4.1 When a note is entered (number typed)
    4.2 When a note is inserted with `a` or `i`, BEFORE the space for the new note is inserted
    4.2 When a note insertion with `a` or `i` is aborted (esc, `h`, `l`, `w`, `b`... but not `j` or `k`) without a number having been entered
    4.3 There might be other scenarios where it would make sense to trigger linting that are not listed here. They should be added explicitly as they are discovered.

[[Bugs]]
These are known bugs that need fixing
- `J` and `K` (uppercases) in tablature mode seem to enter the number 5 (probably because they are mapped to `5j` and `5k`). They should not do this, they should behave as normal movements.

[Chords]

Chords can appear anywhere in a `.song.txt`, the following are valid chords:
Am
F#sus4
Dadd9
Bsus2

[[Rendering]]
Chords MUST be highlighted in magenta wherever they are in the document. ✓
There will be false positives (like `A` for an A major chord is likely to appear as a word in prose): it's okay, we'll just accept it for simplicity. ✓

[[Editing]]
- `<Ctrl-A>` / `<Ctrl-X>` — transpose chord under cursor up/down ✓
- `<leader>m` — toggle minor/major ✓
- `:SongwriterChordAbove <chord>` — insert chord above cursor, aligned to cursor column ✓
- `:SongwriterChordQuality <quality>` — change quality of chord under cursor ✓


[Chord annotations]

We can have lyrics with chord annotations above them. These look like (we'll use backticks here for clear specifications, but backticks are not part of this format):

```
Am
I walk a lonely road
Gm                F
The only one that I have ever known
Don't know where it goes
         Bm
But it's home to me and I walk alone
```

There is nothing special about the rendering of these (just normal chord and prose rendering) ✓, but there might be some features to come for editing. ✗
