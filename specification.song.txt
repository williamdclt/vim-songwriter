[Context]

This file is a specification of this format, and also a valid example of this format.

`.song.txt` files contain different types of content.


[Sections]

Sections are marked by square brackets (eg `[Intro]`). We can assume that they are standalone on a line. They should be rendered in bold and highlighted in yellow. ✓
We can have subsections by adding more brackets, eg `[[Chorus]]`): these should also be bold yellow. ✓


[Prose]

We can have prose anywhere in a `.song.txt`. This should just be rendered with default colours. ✓


[Tablature]

Guitar tablature is a format to represent sequence of notes as played on a guitar. It looks like this:

e|-----------4--|--1-----------|--3-----------|--3------------|
B|--------1-----|-----2-----2--|--------------|---------4--1--|
G|--3-----0--0--|-----1--0--0--|--1-----------|---------------|
D|--------1-----|-----1--------|--5--1--------|------1--1-----|
A|--4--3--------|--1-----1-----|--5--3--3--3--|---------3--1--|
E|--3-----------|--1-----------|-----1--------|------3--4--4--|

Each line is a guitar string, the numbers are the fretted notes, played sequentially from left to right.

A note is a fret (digits: `12` is one note) or `x` (a muted note). Anything else between notes (playing techniques such as `h`, `p`, `/`, `b`, `~`, or any other notation) is a separator: like a dash it only takes up space and has no time column of its own, but unlike a dash it is preserved. So `5h7` is two notes, and the 7 has its own time column. A chain is a run of notes and separators with no dash in it (`5h7`, `7~`, `x`).

[[Rendering]]
1. String names (EADGBe at the start of the line) MUST be in blue ✓
2. Dashes MUST be in blue ✓
3. everything else in white ✓
4. In tablature mode, the time column under the cursor (the notes starting on the cursor's column, on every string of the tab) is highlighted, so it is clear which notes column-wise operations act on. Highlighting only: the file is unchanged. ✗

[[Motions]]
1. Motions like `w` MUST stop on `|` (as well as `dw`, `cw`...) ✓
2. Motions like `w` MUST NOT stop on `-` ✓
3. `W` (uppercase) MUST jump to the next `|` (in tablature mode, see [[Editing]] 3.5) ✓
4. `B` (uppercase) MUST jump to the previous `|` (in tablature mode, see [[Editing]] 3.5) ✓
5. Outside tablature mode, `L` and `H` keep their native meaning (bottom / top of the window); in tablature mode, see [[Editing]] 3.3.5. ✓

[[Editing]]
1. `||` should lint the current tablature. A line whose last bar has no closing pipe (`e|--3--5--`) gets one: that bar is linted like any other, never dropped (`e|--3--5--|`). Whitespace after the final pipe is not a bar. ✓
    1.1 If some pipes bounding a bar are not vertically aligned across all strings, add dashes as necessary to align them. ✓
    1.2 Trim start and end dashes so that there is exactly 2 dashes after/before the pipes bounding the bar. Empty bars should have 5 dashes (`|-----|`), so that a note typed in the middle one needs no reflow (`|--7--|`). ✓
    1.3 Split up numbers that are overlapping but not aligned (when a number is 2-digits, the second digit might overlap with another number on a different line), by pushing the second number to the right with dashes. There needs to be 1 dash between the numbers. ✓
    1.4 If the tab's last bar is empty (no note on any string), delete it; repeat while the new last bar is empty, but always keep at least one bar: a tab left with none (`e||`) gets one empty bar. ✓
    1.5 Separators are kept: each stays at its distance from what precedes it on its string, and counts as content for 1.2. They take no part in 1.3: a note may line up under a separator or under the fret after it. If a note is pushed away, the separator stays with what precedes it (`5h7` -> `5h--7`). ✓
2. In normal mode, `_` should insert a dash (`-`) at the cursor's column position on every line of the tab. ✓
3. `<leader>t` should toggle a special "tablature" mode. It is on when a `.song.txt` is opened. ✓
    Like Vim, tablature mode has a normal state and an insert state. In the normal state (the default), moving never changes the file: motions only move the cursor, and nothing is linted. The insert state is for writing notes: moving across notes opens space for new ones (3.3.3). ✓
    3.1 `a` should create space for a new note to be entered, and enter the insert state. ✓
        3.1.1 it should add dashes to the right (across all lines) to create space for a new note: at least one dash separation with the previous note and the next note (or the pipe). ✓
        3.1.2 it should move the cursor to where the new note would be: one dash apart from the current note ✓
        3.1.3 Between two notes joined by a separator, the separator stays with the note on the far side: `a` on the 5 of `5h7` gives `5--h7`, so a digit gives `5-3h7`. A separator with no note beyond it belongs to its note, and the slot goes past it (`a` on `7b`, `i` on `/5`). ✓
        3.1.4 `i` does the same to the left of the note. `c` (6.6), `o` / `O` (8) and `:SongwriterNewTab` (9) also open a slot and enter the insert state. ✓
        3.1.5 `<Esc>` leaves the insert state, closing an open slot (4.3). Any other change to the file (`u`, `x`, `p`, an operator...) leaves it too. ✓
        3.1.6 The insert state is visible: `-- TAB INSERT --` is shown when it is entered, and `songwriter#keys#Mode()` returns `TAB INSERT` (empty otherwise) for use in a status line. ✓
    3.2 Word motions move along the cursor's string, by word. A word is a chain (a dash is the space between words, a separator is part of the word), so `5h7` is one word. `w` moves to the first note of the next word, `b` to the first note of the word under the cursor, or of the previous one when already there. `e` moves to the last note of the word under the cursor, or of the next one when already there, and `ge` to the last note of the previous word. Dashes and pipes are never stops, and a two-digit fret is landed on at its first digit. Within a word, `l` and `h` reach each note (3.3). In the insert state, they close an open slot (4.3) and never open one. ✓
    3.3 `l` and `h` move across notes. ✓
        3.3.1 `l` should move to the column where _any_ line has a note. ✓
        3.3.2 In the normal state, `l` and `h` only move: with no column further that way, the cursor stays. `h` does the opposite of `l` (moving left). ✓
        3.3.3 In the insert state, the gaps between notes are stops too. On a note, `l` opens a slot after it as `a` does, and `h` a slot before it as `i` does. On a slot, `l` / `h` close it (4.3) and move to the next / previous note. With the cursor on the 3 of `e|--3-5--|`: `l` opens a slot between 3 and 5 (`e|--3---5--|`, cursor on the middle dash), `l` again closes it and lands on 5 (`e|--3-5--|`), `l` again opens a slot after 5. Crossing a bar line, each gap is visited once: from the last note of a bar, `l` opens a slot in that bar, then the next `l` goes to the first note of the next bar. ✓
        3.3.4 An empty bar (no note on any string) is a stop of its own for `l` and `h`, on its middle dash. In the insert state, landing there opens a slot in its middle (`e|--4--|--|--1--|` -> `e|--4--|-----|--1--|`), ready for a digit; left without a note, it is closed as any slot (4.3). ✓
        3.3.5 `L` and `H` move to the next / previous stop as `l` and `h` do in the normal state, in both states: they never open a slot, so they are the quick way through notes in the insert state. There, they close an open slot first (4.3) and go on from the note it was opened by, as `l` / `h` would. After an operator and in visual mode, they are `l` / `h` (6.2.1, 6.9.5). ✓
    3.4 numbers should enter the note: replace the character under cursor with the number. On a note, the whole note is replaced. ✓
        3.4.1 A digit typed straight after another one (without moving or editing in between) is appended to it, so two-digit frets can be typed (`1` then `2` gives `12`). ✓
            3.4.1.1 In the insert state, the digit is appended only when the fret it makes exists: no leading zero, and at most `g:songwriter_max_fret` (24 by default). Otherwise the note just typed is done, and the digit opens a slot after it, as `l` would (3.3.3), and is entered there: `a5` then `7` gives `5-7`, `a1` then `2` gives `12`, `a2` then `5` gives `2-5`. A digit straight after a muted note (`x`, 3.4.3) opens a slot the same way (`ax7` gives `x-7`). So a run of notes is typed without `l` in between. Moving (`j` / `k` to build a chord) ends the typing, so the next digit goes where the cursor is. Each note is its own undo step with its slot. ✓
            3.4.1.2 In the insert state, `<Space>` is `l` (3.3.3): it ends a note whose next digit would be appended (`a1<Space>5` gives `1-5`). ✓
            3.4.1.3 In the insert state, a separator typed straight after a note (`h`, `p`, `b`, `r`, `t`, `s`, `/`, `~`) is written right after it, and a digit typed straight after the separator starts the next note of the chain there: `a5h7` gives `5h7`. Room is made on every string, so the notes after it keep their gap. The note and its separators are one undo step. These keys have their usual meaning anywhere else (after any other key). ✓
        3.4.2 A digit on a separator does nothing (except straight after typing it, 3.4.1.3). Separators are edited with Vim's own `f` and `r`, which tablature mode leaves alone (`fhr/` turns a hammer-on into a slide, `f-rh` adds one). ✓
        3.4.3 `x` on a dash enters a muted note, like a digit (the note is linted and any open slot is filled). On a note, `x` erases it (6.7). ✓
    3.5 Bar motions, as Vim's WORD motions are a bigger `w`/`b`/`e` ([[Motions]] 3-4): `W` moves to the first time column of the next bar; `B` to the first time column of the cursor's bar, or of the previous bar when the cursor is already there (or before it); `E` to the last time column of the cursor's bar, or of the next bar when the cursor is already there (or after it). On a pipe, the cursor's bar is the one after it for `W`/`E` and the one before it for `B`. A bar with no note: its middle dash. No such bar: the cursor stays. In the insert state, they close an open slot (4.3) and never open one. After an operator, `W`/`B` keep the pipe motion (`dW` is `D`, 6.8.1). Counts repeat them (`2W`). ✓
    3.6 In the insert state, the arrow keys carry the note under the cursor through the tab (its separators stay where they are). `<Up>` / `<Down>` move it one string up / down, keeping its fret. `<Right>` / `<Left>` move it through the stops of `l` / `h` (3.3.3): from a note column into the gap after / before it, opening room there as `a` / `i` do, then onto the next column, an empty bar being a stop (3.3.4); past the last note of the tab, into a new bar (5), and back from it into the gap after the last note. A bar the note leaves empty stays a stop (3.3.4) while it is carried, so `<Left>` from a note alone in the last bar stops in an empty bar before it. Where the note was, its column goes if it is left empty, as with `x` (6.7.2), and the room opened in a gap closes when it moves on: with the cursor on the 5 of `e|--3--5--7--|`, `<Right>` gives `e|--3--5--|` (the 5 on the 7's column), `<Right>` again `e|--3--7-5--|`. On a column where its string already has a note, the carried note replaces it, and that note comes back when it moves away. Back where it started, the tab is exactly as it was. The tab is linted after each move, with the cursor on the note; a run of moves is one undo step. Where it cannot go (no string that way, a separator in the way, nothing further right in a new bar), nothing changes. Off a note, and in the normal state, the arrows move the cursor as usual. ✓
4. An edit should trigger linting ✓
    4.1 When a note is entered (number typed) ✓
    4.2 When a note is inserted with `a` or `i`, BEFORE the space for the new note is inserted. Where no slot can open (no note to anchor on), nothing changes, not even the lint. ✓
    4.3 When a slot is closed without a number having been entered (`<Esc>`, `h`, `l`, `w`, `b`... but not `j` or `k`), the tab goes back exactly as it was before the slot was opened (including the lint of 4.2, except after a motion: 4.3.3), and no undo step is left: it is as if the slot was never opened. A slot opened by `c` (6.6), `o` / `O` (8) or `:SongwriterNewTab` (9) is part of a bigger edit, which is kept: closing it lints the tab instead (an empty bar stays as `|-----|`). ✓
        4.3.1 A note typed into a slot is one undo step with the slot (and its lint): `u` after `a7` gives back the tab as it was before `a`. So is a two-digit fret (`a12`). ✓
        4.3.2 Moving in the normal state never lints. ✓
        4.3.3 A slot closed by a motion (`h`, `l`, `w`, `b`, `W`, `B`, `E`, `L`, `H`...) keeps the lint of 4.2: only the slot's own room goes, so an unlinted tab is linted once by `a` / `i` and stays so while moving through it in the insert state. The lint is then an undo step of its own. `<Esc>` straight after `a` / `i` still gives the tab back exactly as it was (4.3). ✓
    4.4 There might be other scenarios where it would make sense to trigger linting that are not listed here. They should be added explicitly as they are discovered.
5. In the insert state, at the end of the tab, moving right (`l`) from the slot after the last note (or from anywhere past it in the tab's last bar) should create a new bar. It should start insertion of a new note so it will be 5 dashes with the cursor in the middle. On that new bar's slot, `l` does nothing. ✓
6. In tablature mode, Vim operators (`d`, `y`, `c`, `p`, `x`...) act on whole time columns across every string of the tab, never on one string alone. Outside tablature mode, everything stays native Vim (single-line editing remains possible there). Spacing between notes is a loose indication of rhythm chosen by the user: operations must preserve it. ✓
    6.1 Text objects. ✓
        6.1.1 `ic` selects the note column under the cursor (on every string); `ac` also includes the gap (dashes) after it, up to the next note column or the bar's closing pipe. On a dash, they select the nearest note column to the left (the bar's first one if there is none). On a pipe, the string name or in an empty bar, they do nothing. ✓
        6.1.2 `i|` selects the content of the bar under the cursor (on every string); `a|` also includes one pipe, so that deleting it leaves no empty `||`. ✓
        6.1.3 Counts extend to the next columns / bars (`d2ac`, `d2a|`): columns never beyond the current bar, bars never beyond the current tab. ✓
        6.1.4 `in` selects the note under the cursor, on its string only; `an` also includes its gap. The register still holds a full-height column, with the other strings as dashes (as `x`, 6.7.3). `yan` copies a single note; `dan` is `x` (6.7); `can` erases the note like `x` and, if its column went with it, opens a slot in its place. ✓
        6.1.5 `iw` selects the word (3.2) under the cursor, on its string only; `aw` also includes the gap after it, as `an` does. On a dash, they select the nearest word to its left in the bar. They act as `in`/`an` do (6.1.4), on every note of the word: `daw` on `5h7` erases both notes as `x` would. ✓
        6.1.6 `iW`/`aW` are `i|`/`a|`: a bar is to a word what Vim's WORD is to its word (3.5). ✓
    6.2 Operators with motions. The reach of an operator follows its motion. ✓
        6.2.1 After an operator, the tablature-mode motions (`w`, `b`, `e`, `ge`, `l`, `h`) are pure motions: they never open a slot. ✓
        6.2.2 The string motions (`l`, `h`, `L`, `H`, `w`, `b`, `e`, `ge`) move along one string, so the operator acts on the notes they cover on the cursor's string only, each as `x` does (6.7): `dl` is `x`, `d3l` erases three notes, `dh` the note before the cursor, `dw` the rest of the word and `db` the part of it before the cursor (or the previous word), `de` the rest of the word. Like `x`, a note whose column is left empty goes with its gap, and the register holds what `x` writes for each note, one after the other. `y` yanks what `d` would delete; `c` deletes, then opens a slot if a column went with it (as `can`, 6.1.4). A motion that covers no note (`dl` on a dash) does nothing. ✓
        6.2.3 Any other target on the current line (`dW`, `d$`, `d0`, `df5`...) gives a column range, which is widened to every string and snapped outward so that a note (e.g. `12`) is never cut in half. A range ending on a note includes its trailing gap (like `ac`); a range starting in a gap snaps to the previous note. A range crossing a bar line closes the bar where it starts (`d$` from a note leaves that bar ending there). ✓
        6.2.4 `j` / `k` after an operator move across strings, so the operator acts on the time column under the cursor, on the strings they cover only: the cursor's string and the next one below (`j`) / above (`k`), or as many more as the count says. Each note is erased as `x` does (6.7): `dj` on the e string erases the column's notes on e and B, `d2k` on the G string those on G, B and e. `dJ` / `dK` reach the bottom / top string, so the lowest or highest notes of a chord go in one step (`dJ` on the D string of an open Am leaves its G, B and e notes). Like `x`, a column left with no note goes with its gap; `y` yanks what `d` would delete; `c` deletes, then opens a slot if the column went (as 6.2.2). A whole tab is `dap` (6.3). ✗
    6.3 Line-wise targets (`dap`, `yap`, `d}`, `VV`...) are widened to every tab they touch, whole. Tabs are separated by blank lines, so `ap` is a whole tab. ✓
        6.3.1 `cap` clears every note of the tab but keeps its bars, and tablature mode stays on. Like any lint, emptied bars at the end are then deleted (1.4), so only the first bar is left: `|--3--5--|--7--|` -> `|-----|` (`|-----|`, with the slot open in its middle). ✓
        6.3.2 `p` of a line-wise register puts it after the end of the tab (`P`: before its start), never between strings. Tab lines pasted next to the tab are kept apart from it by a blank line. ✓
    6.4 Registers: column and bar yanks are stored as normal Vim blockwise registers (one row per string), so they interoperate with native Vim (`<C-v>` yanks, pasting outside tablature mode). The string names of the source tab are recorded alongside the register (ignored if the register has changed since). Named registers (`"a`) work as usual. ✓
    6.5 `p` / `P` paste a blockwise register. ✓
        6.5.1 Column register (no pipe in it): inserted after (`p`) / before (`P`) the cursor's note column and its gap. The yanked gap comes along, so spacing is preserved (register `5--`, cursor on 3: `e|--3--7--|` -> `e|--3--5--7--|`). ✓
        6.5.2 Bar register (contains a pipe): inserted after the end (`p`) / before the start (`P`) of the cursor's bar; a bar is never split. ✓
        6.5.3 When the register has a different number of rows than the tab, rows are matched from the bottom string (a bass tab `GDAE` lands on the lowest 4 strings of a guitar tab; extra strings get dashes; extra rows are dropped). If the source string names are known and differ where they meet (drop D vs E, 5-string bass, 7-string guitar), refuse with a message. If unknown, paste and say rows were matched by position. If dropped rows contained notes, paste and say how many notes were dropped. ✓
        6.5.4 A character-wise register is refused with a message. ✓
        6.5.5 The cursor lands on the first pasted note. ✓
    6.6 `c{target}` deletes like `d{target}`, then opens a slot where the deleted content was (as `a` does, 3.1), ready for a digit, in the insert state. ✓
    6.7 `x` erases the note under the cursor on the current string. ✓
        6.7.1 If another string has a note on the same column, the note becomes dashes (same width) and the column is kept. ✓
        6.7.2 If no other string has a note on that column, the note and its gap up to the next note column (or the bar's closing pipe) are removed on every string, so the following notes move earlier and the previous note keeps its gap (`e|--3----5--7--|`, `x` on 5 -> `e|--3----7--|`). Rests are only created explicitly, with `_`. Another string's notes stay as they are: less of the gap is removed where they need it, so a dash stays between two of them (a `3` on B between the 7s of `5h7--7b` on e: `5h7-7b`), and where even the note's own column cannot go (a note under the dash of `10-12`), the note becomes dashes as in 6.7.1. ✓
        6.7.3 `x` writes to the register what `ac` would yank, with every other string as dashes. So `xp` swaps a note with the next column, as in normal Vim. ✓
        6.7.4 A separator after the erased note is part of its gap and goes with it (`x` on the 5 of `5h7` -> `7`). One before it stays (`x` on the 7 of `5h7` -> `5h`). ✓
    6.8 Doubled operators act on the time column under the cursor, as they act on a line in text: `dd` is `dac`, `yy` and `Y` are `yac`, `cc` is `cac` (`S` is not: it starts the string moves of 7). A count goes after the operator (`d3d`). So `ddp` swaps a column with the next one and `yyp` duplicates it. ✓
        6.8.1 `D` / `C` delete / change to the end of the bar (`dW` / `cW`). ✓
        6.8.2 `X` keeps its native meaning. ✓
    6.9 Visual mode. ✓
        6.9.1 `ic`/`ac`/`i|`/`a|` in visual mode select a blockwise rectangle covering every string, and repeating them extends the selection (`va|a|`). The cursor is on the rectangle's bottom-string corner. ✓
        6.9.6 `in`/`an` and `iw`/`aw` in visual mode select the note or the word on its string; an operator then acts as on `in`/`an` (6.1.4, 6.1.5). `iW`/`aW` are `i|`/`a|`. ✓
        6.9.2 A plain `v` selection (or a `<C-v>` covering only some strings) is shown as-is, and widened and snapped as in 6.2.3 when an operator is applied. ✓
        6.9.3 `V` starts a column selection: a blockwise selection of the cursor's column on every string of the tab, cursor on the bottom string, extended by the motions of 6.9.5 and snapped as in 6.9.2 by an operator. In a `v` or `<C-v>` selection, `j`/`k` never leave the tab's strings. `V` again (`VV`) switches to native line-wise visual, which selects whole tabs (6.3). ✓
        6.9.4 Visual `p` replaces the selected columns with the register (delete, then paste in their place, with 6.5.3 row matching). ✓
        6.9.5 Tab motions (`w`, `b`, `e`, `ge`, `l`, `h`, `L`, `H`, `W`, `B`, `E`) work in visual mode without leaving it. ✓
    6.10 Each operation, including the lints before and after it, is a single undo step, and `.` repeats it (with its register). After a yank, `.` repeats the yank. ✓
    6.11 After `d`, `x` (6.7.2) and `p`, the tab is linted, and the cursor is on the first note at or after the change, or, with none (the change was at the end of the tab, e.g. its last bar went), on the last note before it. Lint trimming to 2 dashes at bar edges (1.2) still applies: a rest left at the start or end of a bar disappears. ✓
    6.12 Digits enter notes in tablature mode (3.4), so a count cannot be typed in front of a command (`3x` types a 3). Counts work after an operator (`d2ac`, `d3w`, `d3d`) and in visual mode. ✓
    6.13 `>>` moves the time column under the cursor one dash later, by inserting a dash before it on every string (what follows moves with it). `<<` moves it one dash earlier, by removing a dash before it (never a separator), but never closer than one dash to the previous note. On a bar's first column they change nothing, since lint keeps two dashes after the pipe (1.2). `.` repeats them. ✓
    6.14 `gp` overlays a column register onto the time column under the cursor, without adding time: the register's notes are written on their strings at that column (rows matched as in 6.5.3), for example to add a bass note under an existing chord. If a note would replace anything but dashes, nothing is pasted and a message says so. A bar register is refused. ✓
7. In tablature mode, `s` and `S` followed by `k` / `j` move notes to the string above / below, keeping their time column (the notes starting on the same column, on every string, played together). ✓
    7.1 `sk`/`sj` (`Sk`/`Sj`) move the chain under the cursor (a hammer-on stays on one string, so `5h7` moves whole). `sK`/`sJ` (`SK`/`SJ`) move the whole time column under the cursor: every chain starting on that column, each by one string. For a column, the cursor may be on any string of it, even on a dash. ✓
    7.2 `s` keeps the fret: the chain moves unchanged (`5` on `e` -> `5` on `B`, `5h7` as a whole). ✓
    7.3 `S` keeps the pitch: every fret of the chain changes by the interval between its two strings, read from the string names (`7` on `G` -> `3` on `B`; `5h7` on `D` -> `0h2` on `G`; on drop D, `7` on `D` -> `0` on `A`). Strings are taken to be listed from the highest to the lowest, neighbouring strings less than an octave apart. Marks without a fret (`x`) move unchanged. ✓
    7.4 A move is refused with a message, leaving the tab unchanged, when: there is no note (`s`/`S` + `k`/`j`) or no time column (`K`/`J`) under the cursor; a note of the time column is in a chain that starts earlier (`K`/`J` on the 7 of `5h7`); there is no string in that direction (for a column: one of its notes is on the top / bottom string); the destination string already has a note there; `S` would make a fret negative; `S` meets a string name that is not a note (A to G). ✓
    7.5 Moved notes leave dashes behind. When a note gets wider (`7` -> `12`) and would touch the next note (or the pipe) on its new string, dashes are inserted on every string to make room. Then the tab is linted. ✓
    7.6 The cursor moves one string with the notes (staying inside the tab), so a move can be repeated. Each move is one undo step, and `.` repeats it. ✓
8. In tablature mode, `o` / `O` add a new tab under / over the current one, kept apart from it by a blank line. It has the same string names and a single bar with a slot open in its middle (`e|-----|`), and the cursor lands on the slot on the same string, ready for a digit (`e|--7--|`). It is in the insert state. Abandoned without a note, the slot is linted (4.3), leaving an empty bar: `e|-----|`. ✓
9. `:SongwriterNewTab [names]` starts a tab from scratch, anywhere in the file: string names one letter each, highest first (default `eBGDAE`, so `:SongwriterNewTab GDAE` for a bass). In a tab it goes under that tab; on a blank line it takes that line's place; elsewhere it goes under the cursor's line. A blank line keeps it apart from a neighbouring tab. Like `o` (8), it has a single bar with a slot open in its middle; the cursor lands on the slot of the top string, in tablature mode and its insert state. ✓
10. In tablature mode, a whole chord is entered on a time column at once. ✓
    10.1 `=` followed by a chord name and `<CR>` (`=Am<CR>`) writes a voicing of that chord on the time column under the cursor, with its root on the cursor's string: on the A string `=Am` gives the open Am (`x02210`), on the low E string the barre at the 5th fret (`577555`). The root's letter may be lowercase (`=am` is `Am`); the quality keeps its case (`M7` is `maj7`, `m7` is minor). Strings the voicing does not play are left as dashes. `<Esc>` or an empty name cancels. ✓
    10.2 Voicings come from the CAGED shapes in standard tuning (`eBGDAE`): the E shape (root on the low E string), the A shape (root on A) and the D shape (root on D) at any fret, and the C and G shapes in open position only (open C, open G). Qualities: major, `m`, `7`, `m7`, `maj7`, `sus2`, `sus4` (or `sus`), where the shape has them: the E shape has no `sus2`, the C and G shapes only major, `7` and `maj7`. `min` is `m` and `M7` is `maj7`. ✓
    10.3 A power chord (`=E5`) is the root, the fifth on the string above and the octave on the one above that, in any tuning: frets are read from the string names, as for 7.3. Any string with two strings above it can be the root. ✓
    10.4 `==` straight after a chord was entered (nothing else typed since) replaces it with the next voicing of the same chord. Voicings are ordered by root string: the cursor's string, then each lower string in turn, then each higher one; on a string, from the lowest fret, an open-position shape first. Then come the same shapes an octave up, at the 12th fret (for chords whose root fret is 0), then the first voicing again. So on the A string, `=A<CR>` then `==` cycles through the open A, the E shape at the 5th fret, the D shape at the 7th and the A shape at the 12th. When the cursor's string roots no voicing (`=Am` on the B string), the first is on the nearest lower string. A message names the chord, its root string and fret, and its place in the cycle (`Am: root on A, fret 0 (1/4)`). ✓
    10.5 The chord replaces the time column under the cursor: on a note column, every note starting there; on a dash or an open slot (3.3.3), it is written there, filling the slot as a digit does. Then the tab is linted (4.1); the cursor stays on its string, on the chord's column. A chord, the slot it filled and its `==` cycles are one undo step. In the insert state, a digit typed straight after a chord opens a slot after it, as after a note (3.4.1.1). ✓
    10.6 A chord is refused with a message, leaving the tab unchanged, when: the name is not a chord or is a slash chord; no shape has its quality; the tuning is not standard (except for power chords); no string roots a voicing; the cursor is on a pipe or a string name; a note on another string covers the column. `==` is refused when no chord was entered just before. ✓
    10.7 `=` followed by a quality alone (`=m7<CR>`, `=M7<CR>`, `=sus4<CR>`, `=5<CR>`) changes the chord on the time column under the cursor to that quality, keeping its root. The root is the note on the lowest string of the column that has a fret (whatever else the column holds, even a single note): on an open `Em`, `=M7` gives `Emaj7`. The new chord is the voicing rooted on that string at that fret when there is one (`Em` at the 12th fret stays at the 12th fret), else the first voicing of 10.4 from that string; it replaces the column as 10.5 does, and `==` cycles from it. A name is a quality when it is not a chord itself (`m`, `7`, `M7`, `sus4`, `add9`, `dim`: `b` is the chord B). Refused with a message when the column has no fretted note, its root string's name is not a note, or as in 10.6. ✓
    10.8 `+` on a note turns it into a power chord rooted on it (fifth and octave on the next two strings above, as 10.3). `+` again extends it to the major chord on the same root, and `+` once more to the minor chord; `+` on that minor chord does nothing. Which step comes next is read from the time column itself, so it also works on a chord entered with `=`: the column must hold exactly the voicing (as 10.2, 10.3) rooted on the note under the cursor, at its fret, and nothing else; any other column gets the power chord. The chord is the voicing rooted on the cursor's string at that fret (the first of 10.4 when there are several), and is placed as 10.5 (one undo step; `==` cycles from it). Refused with a message, leaving the tab unchanged, when the cursor is not on a fretted note, its string name is not a note, no voicing is rooted on that string at that fret (no two strings above for a power chord, no shape rooted on the G or B string), the tuning is not standard (for the major and minor chords), or as in 10.6. ✓

[[Bugs]]
These are known bugs that need fixing (none known).

[Chords]

Chords can appear anywhere in a `.song.txt`, the following are valid chords:
Am
F#sus4
Dadd9
Bsus2

[[Rendering]]
Chords MUST be highlighted in magenta wherever they are in the document. ✓
There will be false positives (like `A` for an A major chord is likely to appear as a word in prose): it's okay, we'll just accept it for simplicity. ✓

[[Editing]]
- `<Ctrl-A>` / `<Ctrl-X>` — transpose chord under cursor up/down (by the count's number of semitones) ✓. Off a chord, they keep Vim's normal behaviour of incrementing/decrementing the next number on the line; on a tab line, dashes are not minus signs (`--3` is fret 3). ✓
    In visual mode, they transpose every chord the selection touches; a selected line with no chord keeps Vim's visual increment of its first number (frets unsigned on a tab line). The selection stays, so they can be pressed again. ✓
- A chord is a whole token: a root, a known quality and an optional `/bass` (`Bad` and `xAm` are not chords). A slash chord is edited as one chord (`D/F#` transposes to `D#/G`, toggles to `Dm/F#`). ✓
- `<leader>m` — toggle minor/major ✓
- `:SongwriterChordAbove <chord>` — insert chord above cursor, aligned to cursor column ✓
- `:SongwriterChordQuality <quality>` — change quality of chord under cursor ✓


[Chord annotations]

We can have lyrics with chord annotations above them. These look like (we'll use backticks here for clear specifications, but backticks are not part of this format):

```
Am
I walk a lonely road
Gm                F
The only one that I have ever known
Don't know where it goes
         Bm
But it's home to me and I walk alone
```

There is nothing special about the rendering of these (just normal chord and prose rendering) ✓, but there might be some features to come for editing. ✗
